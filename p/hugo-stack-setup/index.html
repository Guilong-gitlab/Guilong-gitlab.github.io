Hugo 建站（一）：使用 Stack 主题搭建与发布个人网站

从本地预览、主题配置到 GitHub Pages 发布，记录本站使用的 Hugo 工作流程。

2025-02-26
阅读时长: 3 分钟

本文以本站的 Hugo + Stack + GitHub Pages 为例，按“准备环境 → 本地预览 → 写文章 → 发布”的顺序说明。本站部署工作流固定使用 Hugo Extended 0.147.9；复现时先保持版本一致，再单独处理升级。

1. 准备环境

需要 Git 和 Hugo Extended。Windows 可用 Chocolatey 安装 hugo-extended，Linux 可从 Hugo Releases 下载对应系统的 Extended 包。安装后打开新终端检查：

1
2

git --version
hugo version

输出应含 extended。本站主题使用 SCSS，普通版 Hugo 不能替代这一版本。使用 VS Code 可以方便地编辑 Markdown；Go 是否必需取决于是否使用 Hugo Modules，不能把它当作所有建站方式的前提。

2. 已有网站与新建网站

维护本站

进入含有 hugo.yaml 的仓库根目录，运行：

1

hugo server -D

打开终端显示的本地地址，通常是 http://localhost:1313/。修改 content/ 中的文件后观察页面刷新。-D 用于预览草稿。

从零建立新站点

以下命令只在创建新网站时运行，不要在已有仓库内重复创建：

1
2
3
4

hugo new site my-site --format yaml
cd my-site
git init
git submodule add https://github.com/CaiJimmy/hugo-theme-stack.git themes/hugo-theme-stack

将主题的示例配置作为起点，按主题对应版本的说明调整。新主题可能要求不同的 Hugo 版本；主题与 Hugo 应作为一组固定下来。本站已把主题文件放在 themes/hugo-theme-stack/，维护本站时无需再添加同名子模块。

3. 认识目录与配置

路径用途
hugo.yaml站点标题、语言、菜单和主题配置
content/post/正式文章
content/page/关于、阅读导航、搜索和归档
assets/需要 Hugo 处理的图片和样式资源
static/按原路径复制到网站的静态文件
themes/hugo-theme-stack/本站主题
.github/workflows/web.yaml本站自动构建与发布流程
public/构建生成的结果，不在这里编辑原文

## 操作步骤

这里写具体内容。

文章页面已经显示标题，正文从二级标题开始即可。draft: true 的文章只在启用草稿的预览中显示；准备发布时改为 false。写作格式见 Markdown 排版。

5. 本地检查

1
2

hugo
hugo server

先看构建是否报错，再检查首页、文章目录、图片、搜索和手机宽度。若文章没有出现，依次检查草稿标记、发布日期是否在未来、文件位置以及头部格式。线上样式缺失时还要检查 baseURL 是否与实际访问地址一致。

6. 发布到 GitHub Pages

本站采用的方式：源文件与发布仓库分离

本站的 .github/workflows/web.yaml 在源仓库 main 分支更新时构建网站，并把 public/ 发布到 Guilong-gitlab/Guilong-gitlab.github.io 的 main 分支。它使用仓库 Secret MYWEB_TOKEN 授权写入目标仓库。令牌只保存在 Secrets 中。

发布前确认目标仓库的 Pages 配置使用发布分支的根目录。推送源文件后，在源仓库 Actions 中检查构建与推送结果，再到目标仓库确认 Pages 发布成功。源仓库是否公开与生成网页是否公开是两个独立设置。

新网站的另一种方式：GitHub Actions 直接部署 Pages

若采用 Hugo 官方的 Pages 工作流，在仓库 Settings → Pages 中选择 GitHub Actions，并按 Hugo 官方部署说明 创建工作流。该方式通过 Pages artifact 发布，与本站的跨仓库分支发布流程不同，不要把两套配置直接拼在一起。

用户主页仓库通常命名为 账号.github.io；项目网站则需要在 baseURL 中包含仓库路径。构建成功但页面仍旧时，先确认部署任务、访问地址和最新提交，再强制刷新浏览器缓存。

7. 日常维护顺序

  1. 在 content/ 编辑正文和元信息。
  2. 用 hugo server -D 预览草稿。
  3. 发布文章前改为 draft: false，用 hugo 检查正式构建。
  4. 查看 Git 差异，确认没有把令牌或本地缓存加入提交。
  5. 提交并推送后查看 Actions 和 Pages 的结果。

主题扩展应优先放在站点根目录的 layouts/ 中覆盖对应模板，这样更容易升级主题。
