Hugo 建站（二）：Markdown 写作与排版

整理标题、列表、链接、图片、代码、表格和 Hugo 文章头部的常用写法。

2025-02-26
阅读时长: 3 分钟

Markdown 用少量标记组织正文，Hugo 负责把它转换成网页。下面的示例以本站使用的 Stack 主题为背景。

1. 文章信息与标题

文章最前面的 Front Matter 保存标题、日期、摘要和分类；它不是正文。页面已经显示文章标题，正文通常从 ## 开始，子节依次用 ###、####，避免跳级。

只有标题、没有正文的章节先不发布。一个章节至少应说明它解决什么问题，以及读者接下来如何操作或判断结果。

2. 段落、换行与强调

段落之间空一行。同一段落中确实需要换行时，在行尾保留两个空格。

1
2
3

这是第一段。

这是第二段，其中有 **重点**、*强调* 和 `行内代码`。

不要用连续空行控制网页高度，也不要把整段文字都加粗。Obsidian 的 **高亮** 不是本站默认支持的 Markdown 语法；重点可直接使用粗体。

4. 链接与图片

外部链接要填写完整地址，链接文字说明目标内容：

1

[Hugo 文档](https://gohugo.io/documentation/)

站内文章链接可用 Hugo 的 relref 短代码，让构建阶段检查目标是否存在。修改文件路径后，也要同步检查引用它的文章。

图片常用两种存放方式：

存放方式示例路径正文引用
页面资源包content/post/demo/index.md 与同目录的 cover.png![说明](cover.png)
全站静态资源static/images/demo/cover.png![说明](/images/demo/cover.png)

普通单文件文章与旁边的 images/ 文件夹不一定构成页面资源包。不要只检查本地编辑器能否显示图片，还要查看 Hugo 生成的网页。

5. 代码

短命令用行内代码；多行内容使用围栏代码块，并标注语言。下面的外层使用四个反引号，以便展示内层的三个反引号：

1
2
3

```bash
hugo server -D
```

常用语言标记有 bash、powershell、python、yaml、json、tex 和 text。输出结果用 text，不要让读者误把输出当作命令执行。

每个代码块都要闭合。命令、预期输出和解释最好分开写；涉及路径或版本时，在命令前交代适用环境。

6. 引用与表格

引用用于来源摘录或简短说明：

7. 公式与自定义内容

数学公式是否显示，取决于站点是否加载公式渲染器。代码块中的 TeX 只展示源码，不会变成公式。需要公式编号和引用时，参考 MathJax 配置。

Hugo 的短代码用于嵌入视频等内容，名称和参数取决于主题。本站已启用原始 HTML，但写普通文章时应优先使用 Markdown，减少布局和主题升级带来的兼容问题。

8. 发布前检查

  • 标题与摘要是否能准确说明内容。
  • 所有章节是否有正文，步骤是否包括前提与结果。
  • 代码块是否闭合，语言标记是否正确。
  • 链接是否有地址，图片是否在网页中显示。
  • 文章是否还残留“下次继续”“把结果发给我”等对话文字。
  • 长文是否能通过自动目录找到目标章节。
