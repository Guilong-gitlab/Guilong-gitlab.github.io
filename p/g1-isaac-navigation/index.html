G1 Isaac Nav：场景搭建、定位与导航算法

基于 Isaac Sim、ROS 2 Humble、RTAB-Map 和 Nav2，梳理 G1 导航系统与实验扩展。

2026-09-17
阅读时长: 17 分钟

本文对应 hyeonjin1998/g1_isaac_nav，使用 Ubuntu 22.04、ROS 2 Humble 与 Isaac Sim 5.1.0。Isaac 进程使用 Python 3.11，ROS 进程使用 Python 3.10，分别在独立终端加载环境。它与本站 MuJoCo / Jazzy 教程是两条独立路线。

阅读建议：第 1–5 节了解架构，第 6–10 节完成安装验证，第 11–19 节理解感知与导航，第 20–29 节研究场景和算法扩展，第 30 节以后用作排错与检查。页面目录可以直接跳转到相应章节。

项目：hyeonjin1998/g1_isaac_nav
适用对象：第一次接触 Isaac Sim / ROS 2 / RTAB-Map / Nav2，但希望最终能自己做 G1 导航算法的人。
目标不是“复制命令能跑一次”，而是最终知道 每个进程在干什么、每个话题为何存在、哪里能改场景、哪里能换算法、出错该查什么。

2. 项目到底做了什么

原笔记记录的项目参数如下；它们用于理解该实现，不是 G1 或 Nav2 的通用配置，复现时应与所用提交对应的代码核对：

  • G1 为 29DOF。
  • 物理仿真频率约 200 Hz。
  • 行走策略控制周期为 50 Hz。
  • /cmd_vel 不是直接变成轮速，而是输入神经网络步态策略。
  • 策略观测维数为 96。
  • 网络输出 29 个关节动作。
  • 仿真进程使用 Python 3.11。
  • ROS 2 Humble 进程使用 Python 3.10。
  • 两边通过 DDS 互通。
  • 建图与定位使用 RTAB-Map。
  • 导航使用 Nav2。
  • 当前局部控制器选择 RPP，而不是把 G1当作普通全向底盘。
  • base_footprint 用作 Nav2 机器人基准坐标系，以减少步态导致 pelvis 上下和滚俯振动对 costmap 的影响。
  • 作者记录的机器人安全半径约 0.30 m。

8. 两套 Python 环境为什么必须分离

这是整个项目第一大坑。 Isaac：

1

Python 3.11

ROS 2 Humble Ubuntu deb：

1

Python 3.10

如果你在 Isaac 虚拟环境里：

1

source /opt/ros/humble/setup.bash

就可能把 Python 3.10 编译的 ROS Python 包路径塞进 Python 3.11。 正确做法：

终端 A

1
2

cd ~/g1_isaac_nav
source scripts/isaac_env.sh

终端 B

1
2

cd ~/g1_isaac_nav
source scripts/ros_env.sh

不要交换。 DDS 关键环境变量应该保持一致，例如开发记录中是：

1
2
3

RMW_IMPLEMENTATION=rmw_fastrtps_cpp
ROS_DOMAIN_ID=0
ROS_LOCALHOST_ONLY=1

检查：

1
2
3

echo $RMW_IMPLEMENTATION
echo $ROS_DOMAIN_ID
echo $ROS_LOCALHOST_ONLY

13. 传感器系统

作者依据 Unitree G1 29DOF 官方 URDF 的安装位姿建立仿真传感器。 开发记录中包括：

  • D435i RGB-D；
  • MID-360 3D LiDAR；
  • torso IMU；
  • pelvis IMU。 其中：
  • D435i 光轴明显向下；
  • MID-360 接近水平。 这意味着：

  • RTAB-Map 与 Nav2 local costmap 的观测范围要和真实传感器视场一致。

17. 为什么当前使用 RPP

作者最初考虑过 MPPI，但 G1 policy 实测后改为：

1

RPP = Regulated Pure Pursuit

原因：

  1. 原地旋转不可靠；
  2. 低速横移不可靠；
  3. 后退精度较差；
  4. “向前走 + 同时转弯”反而比较可靠。 所以更符合：
1
2
3

沿路径向前
+
用曲率产生圆弧转弯

而不是：

1

站着原地调角度

当前开发记录里给出的重要参数思想：

1
2
3
4
5
6
7
8

robot_radius ≈ 0.30 m
desired_linear_vel ≈ 0.6
minimum_speed ≈ 0.4
vx_max ≈ 0.8
vy_max = 0
use_rotate_to_heading = false
allow_reversing = false
xy_goal_tolerance ≈ 0.35

这些不是通用 Nav2 教科书默认值，而是针对该 G1 policy 的实测结果。

34. 当前仓库真实限制

必须明确：

  1. 仓库非常新，提交历史很短。
  2. 作者确实跑通了 G1 行走、传感器、建图和导航链路。
  3. 但开发记录显示“定位模式连续自主导航”的稳定性仍是当前问题。
  4. 重复仓库场景会增加 RTAB-Map错误回环风险。
  5. G1 locomotion policy 对小速度、原地旋转、后退不如轮式底盘。
  6. 因此不能照搬普通 TurtleBot Nav2 参数。
  7. 如果你最终做论文，必须把“导航算法性能”和“定位失效”分开统计，否则结果会混淆。
