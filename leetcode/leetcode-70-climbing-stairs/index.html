LeetCode 70：爬楼梯

从递归超时出发理解重复计算，并学习动态规划和空间优化。

2026-10-06
阅读时长: 5 分钟

题目

假设你正在爬楼梯，需要 n 阶才能到达楼顶。每次可以爬 1 或 2 个台阶，问有多少种不同的方法可以爬到楼顶。

题目链接：LeetCode 70：爬楼梯

例如 n = 3：

1
2
3

1 + 1 + 1
1 + 2
2 + 1

所以一共有 3 种方法。

class Solution:
    def climbStairs(self, n: int) -> int:
        if n == 1:
            return 1
        elif n == 2:
            return 2
        else:
            number_1 = self.climbStairs(n - 2)
            number_2 = self.climbStairs(n - 1)
            return number_1 + number_2

这个思路是正确的。超时不是因为递推关系错了，而是普通递归产生了大量重复计算。

为什么有：

1

f(n) = f(n-1) + f(n-2)

可以从"最后一步"考虑。要到第 n 阶，最后一步只有两种可能：

1
2

最后走1阶 → 之前一定在第 n-1 阶
最后走2阶 → 之前一定在第 n-2 阶

因此：

1
2
3

到第n阶的方法数
= 到第n-1阶的方法数
+ 到第n-2阶的方法数

而：

1
2

f(1) = 1
f(2) = 2

所以：

1
2
3

f(3) = 2 + 1 = 3
f(4) = 3 + 2 = 5
f(5) = 5 + 3 = 8

得到：

1
2

n       1   2   3   4   5   6
方法数  1   2   3   5   8   13

这就是斐波那契形式的递推。

标准解法

既然问题是"算过的东西又重新算"，最直接的办法就是把以前的结果保存起来。

建立：

1

dp = [0] * (n + 1)

规定：

1

dp[i] = 爬到第 i 阶的方法数

已知：

1
2

dp[1] = 1
dp[2] = 2

再根据：

1

f(n) = f(n-1) + f(n-2)

得到：

1

dp[i] = dp[i - 1] + dp[i - 2]

例如 n = 5：

1
2
3
4
5

dp[1] = 1
dp[2] = 2
dp[3] = dp[2] + dp[1] = 3
dp[4] = dp[3] + dp[2] = 5
dp[5] = dp[4] + dp[3] = 8

class Solution:
    def climbStairs(self, n: int) -> int:
        if n == 1:
            return 1

        dp = [0] * (n + 1)
        dp[1] = 1
        dp[2] = 2

        for i in range(3, n + 1):
            dp[i] = dp[i - 1] + dp[i - 2]

        return dp[n]

这就是最基础的动态规划（Dynamic Programming，DP）。现阶段可以先把动态规划理解成：

递归：
需要 f(5)
→ 算 f(4)、f(3)
→ f(4) 又重新算 f(3)、f(2)
→ 大量重复

动态规划：
先算 f(1)，保存
再算 f(2)，保存
利用前面的结果算 f(3)，保存
再算 f(4)
一直算到 f(n)

最核心的思想就是：已经算过的子问题，不要重复计算。

这道题还可以继续优化。观察：

1

dp[i] = dp[i - 1] + dp[i - 2]

计算当前答案时实际上只需要前两个答案，没有必要保存整个 dp 数组。

可以使用：

1

first = 1
second = 2

1
2

current = first + second

得到 3。下一轮需要的是 f(2) 和 f(3)，所以：

1
2

first = second
second = current

两个变量不断向前移动。

class Solution:
    def climbStairs(self, n: int) -> int:
        if n == 1:
            return 1

        first = 1
        second = 2

        for i in range(3, n + 1):
            current = first + second
            first = second
            second = current

        return second

复杂度

先分析我的递归代码。它不是普通的一层循环，而是每个较大的问题继续产生两个子问题：

1
2
3

f(n)
├── f(n-1)
└── f(n-2)

子问题又继续产生新的子问题，递归树迅速膨胀。常用上界表示为：

1

时间复杂度：O(2^n)

更精确地说，它的增长速度与斐波那契数相同，是指数级增长。初学阶段先记住：

1
2
3

普通递归 + 大量重复子问题
→ 指数级增长
→ 很容易超时

空间复杂度也不是 O(1)。虽然没有创建列表，但递归函数调用本身需要占用内存。最长调用链大约是：

1
2
3
4
5

f(n)
→ f(n-1)
→ f(n-2)
→ ...
→ f(1)

递归深度和 n 同级，因此：

1

空间复杂度：O(n)

再看 dp 数组方法：

1
2

for i in range(3, n + 1):
    dp[i] = dp[i - 1] + dp[i - 2]

循环大约执行 n 次，每次只有固定数量的操作，因此：

1

时间复杂度：O(n)

dp 保存大约 n 个结果，因此：

1

空间复杂度：O(n)

最后看两个变量的方法。循环仍然大约执行 n 次：

1

时间复杂度：O(n)

但始终只使用：

1
2
3

first
second
current

几个固定变量，所以：

1

空间复杂度：O(1)

对比：

复盘

我的递归思路本身是正确的，而且已经找到了这道题最关键的递推关系：

1

f(n) = f(n-1) + f(n-2)

因为到达第 n 阶的最后一步只有：

1
2

从 n-1 走1阶过来
从 n-2 走2阶过来

真正导致超时的是同一个 f(k) 被反复计算。

这道题应该建立这样的思考过程：

1. 找递推关系
   f(n) = f(n-1) + f(n-2)

2. 直接递归
   结果正确，但出现大量重复计算

3. 保存以前算过的结果
   → 动态规划
   → O(n) 时间，O(n) 空间

4. 发现每次只需要前两个结果
   → 不保存整个 dp 数组
   → O(n) 时间，O(1) 空间

class Solution:
    def climbStairs(self, n: int) -> int:
        if n == 1:
            return 1

        first = 1
        second = 2

        for i in range(3, n + 1):
            current = first + second
            first = second
            second = current

        return second

这道题真正需要掌握的不是背代码，而是第一次理解：递归关系可能完全正确，但如果同一个子问题被重复计算很多次，程序仍然会非常慢；这时就应该考虑把已经算过的结果保存下来，这就是动态规划最基本的出发点。
