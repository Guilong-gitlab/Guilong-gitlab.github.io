G1 仿真（二）：认识 ROS 2 接口与 RViz 模型

阅读 G1 ROS 2 桥接项目，梳理包结构、模型显示、关节状态与控制接口。

2025-07-04
阅读时长: 6 分钟

本文重点是阅读接口与本地模型显示。上游 SimonR99/unitree_g1_ros2 的 README 标注 ROS 2 Foxy；下面保留的是原笔记的 Humble 环境操作示例，不代表上游已验证 Humble。迁移时应逐项检查依赖和 launch 参数，不能把“包可以编译”当作全部功能兼容。

本篇只启动模型描述与可视化，不把桥接仓库视为自带物理仿真器。完整仿真可直接使用后续的 MuJoCo Docker 路线。

1. 下载项目并认识接口

本节通过目录与源码认识 G1 桥接项目，先检查本地已安装 Git 和目标 ROS 环境。 先下载：

git clone https://github.com/SimonR99/unitree_g1_ros2.git
cd unitree_g1_ros2

pwd

然后看当前目录：

现在先理解这个仓库到底是干嘛的

它不是“G1 导航算法”。 它的作用是：

把宇树 G1 自己内部的数据和控制接口，翻译成标准 ROS2 接口。 你可以把它想成一个翻译器。 G1 内部本来讲的是：

rt/lowstate
rt/sportmodestate
LocoClient.Move()

普通 ROS2 导航程序更喜欢：

1
2
3
4
5

/joint_states
/imu/data
/odom
/cmd_vel
/tf

所以这个仓库做：

1
2
3
4
5
6
7

          Unitree世界
              │
              │
        G1 ROS2 Bridge
              │
              ▼
           ROS2世界

这就是为什么以后 Nav2 能控制 G1。 我的固定路径是：

1

~/workspaces/unitree_g1_ros2

而且这个仓库当前确实是一个完整 ROS2 package 仓库，真正的包在：

1

~/workspaces/unitree_g1_ros2/src/g1_ros2_bridge

仓库自带 G1 的 URDF、mesh、RViz 配置、robot_state_publisher、cmd_vel_bridge、odom_bridge 等。(GitHub)

第一部分：先把这个仓库编译起来

进入你的仓库：

1

cd ~/workspaces/unitree_g1_ros2

先确认：

1

pwd

应该输出：

1

/home/你的用户名/Desktop/unitree/G1_learning/unitree_g1_ros2

再看：

1

ls

应该有：

1
2

README.md
src

再看真正 ROS2 包：

1

ls src

应该看到：

1

g1_ros2_bridge

这就说明目录对了。

第二步：加载你现在的 ROS2 Humble

你的系统是 Ubuntu 22.04 + ROS2 Humble，所以：

1

source /opt/ros/humble/setup.bash

确认：

1

echo $ROS_DISTRO

应该：

1

humble

注意，这个仓库 README 原生写的是 ROS2 Foxy，所以我们现在是在 Humble 上先跑它能独立运行的模型/ROS 标准部分。(GitHub)

第三步：先安装 G1 模型显示需要的东西

执行：

1

sudo apt update

然后：

1
2

4
5

sudo apt install -y \
ros-humble-rviz2 \
ros-humble-robot-state-publisher \
ros-humble-joint-state-publisher \
ros-humble-joint-state-publisher-gui \
ros-humble-xacro \
python3-colcon-common-extensions

这里你暂时只要知道：

1

robot_state_publisher

负责根据 G1 URDF 发布机器人 TF；

1

RViz

负责把 G1 显示出来；

1

joint_state_publisher_gui

可以让你手动拖动 G1 各关节。

第四步：编译这个仓库

还在：

1

cd ~/workspaces/unitree_g1_ros2

执行：

1

colcon build --symlink-install --packages-select g1_ros2_bridge

这个命令分三部分理解：

1

colcon build

编译 ROS2 包；

1

--symlink-install

Python/资源文件修改后不用每次全部复制，适合开发；

1

--packages-select g1_ros2_bridge

只编译这个包。 如果成功，最后应该类似：

1

Summary: 1 package finished

第五步：让 ROS2 认识你刚编译出来的包

执行：

1

source install/setup.bash

然后：

1

ros2 pkg list | grep g1

应该看到：

1

g1_ros2_bridge

如果能看到，说明第一步真正成功了：

ROS2 Humble 已经认识这个 G1 ROS2 包。

第六步：先启动 G1 的“模型描述”

这个仓库自带：

1

description.launch.py

它会启动 G1 的 URDF 和 robot_state_publisher。仓库当前文件结构里明确包含这个 launch。(GitHub) 执行：

1

ros2 launch g1_ros2_bridge description.launch.py

这个终端先不要关。 如果成功，你会看到 robot_state_publisher 启动之类的信息。

第七步：打开 RViz，真正看到 G1

新开一个终端。 重新加载两个环境：

1

source /opt/ros/humble/setup.bash

1

source ~/workspaces/unitree_g1_ros2/install/setup.bash

然后直接使用仓库自带的 RViz 配置：

1

rviz2 -d ~/workspaces/unitree_g1_ros2/src/g1_ros2_bridge/rviz/g1.rviz

如果一切正常，你应该直接看到：

Unitree G1 的 29 自由度模型。 这个仓库当前确实自带 g1_29dof.urdf、35 个 mesh 以及 rviz/g1.rviz。(GitHub)

第十一步：现在再启动仓库真正的 ROS2 Bridge

这个仓库官方启动整套 bridge 的方式是：

1

ros2 launch g1_ros2_bridge robot.launch.py

它会一起启动：

1
2
3
4
5

state_bridge
odom_bridge
cmd_vel_bridge
loco_bridge
robot_state_publisher

仓库 README 当前明确说明这一点。(GitHub) 但你现在没有接 G1 实机，因此不要直接正常模式启动。 先用：

1

ros2 launch g1_ros2_bridge robot.launch.py dry_run:=true enable_camera:=false

这里：

1

dry_run:=true

表示控制命令只记录，不真的让 G1 动；

1

enable_camera:=false

表示先不启 RealSense。 README 也明确提供 dry_run:=true 和 enable_camera:=false。(GitHub)

第十三步：手动给 G1 Bridge 发速度命令

先确认 /cmd_vel：

1

ros2 topic info /cmd_vel

你应该看到类型：

1

geometry_msgs/msg/Twist

然后发一次：

1
2

ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
"{linear: {x: 0.2, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.1}}"

这里：

1

linear.x = 0.2

表示前进；

1

linear.y = 0.0

不横移；

1

angular.z = 0.1

慢慢转弯。

由于现在：

1

dry_run=true

G1 模型不会物理走起来。

但是 cmd_vel_bridge 会收到这个 ROS2 Twist，其核心映射就是：

1
2
3
4
5

/cmd_vel
↓
cmd_vel_bridge.py
↓
LocoClient.Move(vx, vy, vyaw)

这也是仓库明确实现的接口。(GitHub)

为什么现在 RViz 里的 G1 不会“往前走”

这是特别重要的一点。

RViz：

只是可视化器。

它不是：

物理仿真器。

所以：

1

/cmd_vel

不会让 RViz 里的 G1 真正在地面上走。

如果你要看到：

1
2
3
4
5
6
7

G1站着
↓
发 /cmd_vel
↓
G1迈腿
↓
G1真实向前运动

必须接：

1

MuJoCo

或者：

1

Isaac Sim

这就是我们下一阶段要做的事。

本阶段检查与衔接

  1. 能在 src/g1_ros2_bridge 中找到包信息、模型、launch 和桥接节点。
  2. 编译完成后加载 install/setup.bash，ROS 可以找到该包。
  3. RViz 的 Fixed Frame 与已发布的 TF 一致，模型资源可以加载。
  4. 缺少活动关节 TF 时，检查 /joint_states 是否有发布者；本地演示可使用 joint_state_publisher_gui，但不要与真实状态发布者同时发布同一组关节。
  5. 能解释模型显示与物理仿真、速度接口与行走控制之间的区别。

下一步可阅读 Docker 中启动 G1 与 MuJoCo，在仿真中继续观察命令与状态的闭环。
