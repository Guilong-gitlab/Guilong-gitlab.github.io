第五阶段：学习导航算法的使用

maxwellrobotics/g1-ros2 不是单纯的 URDF/RViz 展示项目，它本身就已经把 Unitree G1 + MuJoCo 仿真 + ROS 2 Humble + SLAM Toolbox + Nav2 + 定位 + 激光雷达 + 真机接口 串起来了。README 明确说明它采用 simulation-first，仿真器和真机使用相同 DDS 接口，因此后面从仿真迁移到真机主要是通信接口和 Domain ID 的切换，而不是重写导航程序。(GitHub)

我们后面会真正做到：

电脑里出现一个仿真环境 → G1 站在场景中 → 激光雷达扫描环境 → 建地图 → 地图保存 → G1 在地图里定位 → 你在 RViz 点目标 → G1 自己规划路线并绕障碍走过去 → 最后换成你自己的导航算法 → 再接真机。

但今天现在先只做第 1 步，不往后跳。

确认你的基础环境

这个项目官方推荐的方式比较特殊：

宿主机 Ubuntu 24.04，里面通过 Docker 跑 Ubuntu 22.04 + ROS 2 Humble。 (GitHub) 但是你现在自己的机器本来就是 Ubuntu 22.04.5 + ROS 2 Humble，所以这里我们首先不乱改任何 ROS 环境，也不要卸载你现在的 ROS 2。 先确认下面 6 个东西。 打开终端：

1

Ctrl + Alt + T

然后一条一条执行下面命令。

① Ubuntu 版本 

1

lsb_release -a

正常你应该看到类似：

1
2
3
4

Distributor ID: Ubuntu
Description:    Ubuntu 22.04.5 LTS
Release:        22.04
Codename:       jammy

② ROS 2 版本

执行：

1

printenv ROS_DISTRO

正常应该是：

1

humble

再执行：

1

ros2 --help

只要能出来 ROS 2 的帮助内容就行。

③ Docker 是否安装

执行：

1

docker --version

这里有两种情况。 如果显示类似：

1

Docker version 28.x.x

说明已经安装。 如果显示：

1

docker: command not found

也不要自己装。 停在这里告诉我。

④ Docker Compose

执行：

1

docker compose version

注意这里是：

1

docker compose

中间空格，不是旧版：

1

docker-compose

正常类似：

1

Docker Compose version v2.xx.x

⑤ Git

执行：

1

git --version

正常类似：

⑥ NVIDIA 显卡

执行：

1

nvidia-smi

你之前这台电脑的 RTX 5070 Ti Laptop 已经恢复正常，所以理论上这里应该能正常看到 GPU。 我们后面跑 MuJoCo 可视化时会用到它。

1. 先进入项目

打开终端：

cd ~/Desktop/unitree/G1_learning/g1-ros2

2. 先确认你现在是 X11

这个项目要把 MuJoCo 窗口从 Docker 显示到你的桌面上。 执行：

1

echo $XDG_SESSION_TYPE

你之前系统是 X11，所以正常应该输出：

如果真的是：

1

继续。 因为官方明确说 GUI 模式要求本地 X11，manage.sh start 会给容器开放本地 X11 显示权限。(GitHub)

3. 检查 NVIDIA 能不能给 Docker 用

你刚才的：

1

nvidia-smi

只能证明：

Ubuntu 能使用显卡。 还没有证明： Docker 里面也能使用显卡。 这是两回事。 先执行：

1

which nvidia-container-cli

情况 A

如果输出：

1

/usr/bin/nvidia-container-cli

很好。 说明 NVIDIA Container Toolkit 基本已经安装。

情况 B

如果什么都没有：

1

%

或者：

1

nvidia-container-cli not found

就先停在这里。 因为这个项目的 Docker Compose 会把 NVIDIA GPU 暴露给 MuJoCo，官方也把 NVIDIA Container Toolkit 列为宿主机依赖。(GitHub)

4. 安装这个项目下载依赖所需要的工具

这个现在可以直接做。 执行：

1

sudo apt update

然后：

1

sudo apt install python3-vcstool

系统可能问：

1

Do you want to continue? [Y/n]

输入：

1

y

然后回车。 安装完成以后：

1

vcs --help

只要出来一大堆帮助信息，就是成功。

vcstool 到底是什么？

这个项目不是只有一个 GitHub 仓库。 例如它还需要：

1
2
3

unitree_mujoco
其他 Unitree 依赖
其他 ROS 包

作者没有全部复制进：

1

g1-ros2

而是写到了：

1

workspace.repos

所以：

1

workspace.repos

相当于购物清单：

1
2
3

我要 A 项目
我要 B 项目
我要 C 项目

而：

1

vcs

就是负责：

按着这个购物清单，把这些 Git 仓库统一下载下来。 官方明确要求在宿主机安装 python3-vcstool，因为依赖是在开发容器启动之前下载的。(GitHub)

现在仍然是在：

1

~/Desktop/unitree/G1_learning/g1-ros2

ls -la | grep .env

应该能看到：

1

1

        ↓
得到你自己的配置文件

现在我们不修改它。

7. 下载完以后看看发生了什么

执行：

1

现在你会发现：

里面比刚 clone 仓库时多了很多东西。 这就是第一次真正看到：

import-externals.sh 并不是一句神秘命令，它实际上是在给 ROS workspace 补齐源码。 官方说明这个脚本就是读取 workspace.repos，把第三方项目放进 workspace/src。(GitHub)

8. 启动 G1 开发容器

现在执行：

1

./scripts/manage.sh start

这一条第一次运行时可能输出非常多。 因为它可能需要：

所以第一次输出很多是正常的。

这个报错非常典型，原因已经很明确了：

1

permission denied while trying to connect to the Docker daemon socket

意思不是 Docker 没装，也不是镜像有问题，而是：

你当前这个普通用户 guilong 没权限访问 /var/run/docker.sock

所以现在先把 Docker 普通用户权限 配好。 先执行：

1

sudo usermod -aG docker $USER

这条命令的意思是：

把你当前用户加入 docker 用户组。 然后你可以先临时让当前终端立即生效：

1

newgrp docker

执行后，终端可能看起来没什么明显变化，这是正常的。 接着测试：

1

docker ps

如果不再报：

1

permission denied

而是正常显示类似：

1

CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES

哪怕是空表，也说明权限已经通了。 然后回到项目目录：

1

cd ~/Desktop/unitree/G1_learning/g1-ros2

再执行：

1

./scripts/manage.sh start

这一次它就应该能真正连接 Docker daemon，开始拉取/构建：

1

adyansh04/ros-dev-workspace:jazzy

11. 开始编译整个 G1 系统

执行官方命令：

1

cd /root/workspace

然后：

1

colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_EXPORT_COMPILE_COMMANDS=ON

官方当前 README 就是用这条命令编译整个 workspace。(GitHub)

这里你会看到什么？

大量类似：

1
2
3
4

Starting >>> g1_description
Starting >>> g1_msgs
Starting >>> ...
Finished <<< ...

最后理想情况类似：

1

Summary: XX packages finished

Starting >>>

代表：

1

开始编译这个 package

Finished <<<

代表：

1

这个 package 编译成功

例如：

1

Finished <<< g1_description

意思：

G1 模型包编译成功。 如果出现：

1

Failed <<< xxxx

不要继续。 把：

1

Failed <<< ...

以及它上面大约 30 行错误发给我。

12. 为什么编译完还不能直接 ros2 launch？

因为 ROS 现在还不知道刚才编译出来的 package 在哪。 执行：

1

然后检查：

1

ros2 pkg list | grep g1_bringup

如果看到：

1

g1_bringup

说明：

ROS 2 已经认识这个项目。 这是非常重要的一步。
