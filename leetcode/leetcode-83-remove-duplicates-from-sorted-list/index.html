LeetCode 83：删除排序链表中的重复元素

利用链表指针原地删除有序链表中的重复节点，理解 next 指针修改和连续重复节点的处理。

2026-10-07
阅读时长: 5 分钟

题目

给定一个已排序链表的头节点 head，删除所有重复的元素，使每个元素只出现一次，并返回仍然有序的链表。

题目链接：LeetCode 83：删除排序链表中的重复元素

例如：

1
2
3
4
5

输入：1 → 1 → 2
输出：1 → 2

输入：1 → 1 → 2 → 3 → 3
输出：1 → 2 → 3

这道题有一个很重要的条件：链表已经排序。所以重复元素一定连续出现，例如：

1

1 → 1 → 1 → 2 → 3 → 3

因此只需要比较当前节点和下一个节点，不需要拿当前节点和后面所有节点逐个比较。

# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def deleteDuplicates(self, head: ListNode | None) -> ListNode | None:
        if head is None:
            return None

        cur = head
        while cur.next:
            if cur.next.val == cur.val:
                cur.next = cur.next.next
            else:
                cur = cur.next

        return head

这个答案是完全正确的，而且已经是这道题最推荐的原地链表解法。

首先：

1
2

if head is None:
    return None

处理空链表。如果 head 是 None，说明一个节点都没有，自然也没有重复元素。

然后：

1

cur = head

这里并没有复制一个链表。head 和 cur 一开始只是同时指向第一个节点：

1
2
3
4
5

head
 ↓
[1] → [1] → [2] → None
 ↑
cur

head 始终负责记住链表开头，cur 则负责向后移动和检查节点。

循环：

1

while cur.next:

为什么判断 cur.next 而不是 cur？因为循环里面需要访问：

1

cur.next.val

也就是说，我们不仅需要当前节点存在，还必须保证下一个节点存在。如果：

1
2
3

[1] → [2] → [3] → None
             ↑
            cur

那么 cur.next 已经是 None，没有下一个节点可以比较，循环就应该结束。

核心判断：

1

if cur.next.val == cur.val:

比较当前节点和下一个节点的值。因为链表有序，如果两者相等，就说明 cur.next 是重复节点。

最重要的一句是：

1

cur.next = cur.next.next

假设现在：

1
2
3
4

A       B       C
[1]  →  [1]  →  [2]  → None
 ↑       ↑       ↑
cur   cur.next  cur.next.next

原来的关系是：

1
2

A.next = B
B.next = C

执行：

1

cur.next = cur.next.next

左边 cur.next 就是 A.next，右边 cur.next.next 就是 B.next，也就是节点 C。因此实际上做的是：

1

A.next = C

链表从：

1

A → B → C

变成：

1

A ─────→ C

也就是：

1
2
3
4
5
6
7
8
9

原来：
[1] → [1] → [2]
 ↑
cur

修改后：
[1] ─────→ [2]
 ↑
cur

中间重复的节点已经不在链表的连接关系中了。

所以链表所谓的"删除节点"，很多时候并不是调用一个 delete() 把节点凭空消灭，而是修改前一个节点的 next，让链表绕过这个节点。这一点和数组很不一样：

1
2

数组删除：经常涉及后续元素移动
链表删除：主要修改 next 指针

为什么删除以后 cur 不能马上移动

你的代码这里写得很关键：

1
2
3
4

if cur.next.val == cur.val:
    cur.next = cur.next.next
else:
    cur = cur.next

只有在两个节点不相等的时候才移动 cur。如果刚删除了一个重复节点，cur 不动。

原因是可能存在连续三个甚至更多重复值：

1

1 → 1 → 1 → 2

开始：

1
2
3

cur
 ↓
[1] → [1] → [1] → [2]

第一次发现前两个 1 相同，于是：

1

cur.next = cur.next.next

得到：

1
2
3

cur
 ↓
[1] → [1] → [2]

注意，此时 cur 后面仍然是 1，所以必须让 cur 留在原地，再比较一次。第二次仍然相等，再删除：

1
2
3

cur
 ↓
[1] → [2]

现在：

1
2

cur.val = 1
cur.next.val = 2

不相等了，说明当前这个 1 的重复节点已经全部处理完，这时才：

1

cur = cur.next

移动到 2。

因此可以记成：

1
2
3
4
5
6
7
8

发现重复：
删除 cur.next
cur 不动
因为新的 cur.next 可能还是重复值

没有重复：
当前值已经处理完
cur 向后移动

完整运行一次

例如：

1

1 → 1 → 2 → 3 → 3

开始：

1
2
3

cur
 ↓
[1] → [1] → [2] → [3] → [3]

1 == 1，所以删除第二个 1：

1
2
3

cur
 ↓
[1] → [2] → [3] → [3]

cur 不移动。再次比较，1 != 2，所以：

1

cur = cur.next

得到：

1
2
3

       cur
        ↓
[1] → [2] → [3] → [3]

2 != 3，继续移动：

1
2

              cur
               ↓
[1] → [2] → [3] → [3]

3 == 3，所以绕过后面的重复节点：

1
2
3

              cur
               ↓
[1] → [2] → [3] → None

现在 cur.next 是 None，循环结束，返回：

1

1 → 2 → 3

为什么最后返回 head

循环过程中：

1

cur = cur.next

会不断向后移动，所以循环结束时 cur 通常已经在链表尾部：

1
2
3
4
5

head
 ↓
[1] → [2] → [3] → None
             ↑
            cur

如果返回：

1

return cur

就只能从最后一个节点开始访问，结果相当于只剩：

1

3

而 head 一直留在第一个节点，所以：

1

return head

才能返回整个处理后的链表。

这也再次说明：

1

cur = head

不是复制链表，而只是两个变量暂时指向同一个节点。之后 cur 可以移动，head 仍然留在开头。

标准解法

你的代码本身就是标准解法：

class Solution:
    def deleteDuplicates(self, head: ListNode | None) -> ListNode | None:
        if head is None:
            return None

        cur = head

        while cur.next:
            if cur.val == cur.next.val:
                cur.next = cur.next.next
            else:
                cur = cur.next

        return head

这里：

1

cur.next.val == cur.val

和：

1

cur.val == cur.next.val

完全等价，所以和你的代码没有算法上的区别。

这道题也不需要使用之前合并链表时学过的：

1

dummy = ListNode()

原因是这道题不会真正删除第一个节点本身。例如：

1

1 → 1 → 1 → 2

题目要求每个元素保留一次，所以第一个 1 可以一直作为 head 保留下来，只需要删除它后面的重复 1。因此直接从：

1

cur = head

开始即可。

复杂度

定义：

1

n = 链表中的节点数量

虽然删除重复节点时 cur 没有向后移动，但被删除的节点已经被链表绕过，不会再次处理。每个节点最终只会出现两种情况：

1
2

不是重复节点 → cur 移动经过它
是重复节点   → 被 cur.next = cur.next.next 绕过

因此所有节点总共只需要处理一遍，时间复杂度是：

1

O(n)

空间方面只使用了 head、cur 等固定数量的变量，没有创建随着 n 增长的新列表、栈或者链表，因此：

1

O(1)

你的答案和标准答案实际上就是同一种算法：

1
2
3

                    我的答案        标准答案
时间复杂度          O(n)            O(n)
空间复杂度          O(1)            O(1)

class Solution:
    def deleteDuplicates(self, head: ListNode | None) -> ListNode | None:
        if head is None:
            return None

        cur = head

        while cur.next:
            if cur.next.val == cur.val:
                cur.next = cur.next.next
            else:
                cur = cur.next

最重要的是理解三个地方。

第一，链表已经有序，所以重复元素一定连续出现：

1

1 → 1 → 1 → 2 → 3 → 3

因此只需要比较：

1
2

cur.val
cur.next.val

第二，链表删除节点的核心是修改指针：

1

cur.next = cur.next.next

也就是：

1
2
3
4
5
6

原来：
A → B → C

B重复，修改A.next：

A ───→ C

让链表直接绕过 B。

第三，删除重复节点以后 cur 不能立即移动，因为可能存在：

1

1 → 1 → 1 → 1 → 2

所以：

1
2
3
4
5
6

重复：
cur.next = cur.next.next
cur 不动

不重复：
cur = cur.next

复杂度：

1
2

时间：O(n)
空间：O(1)

这道题应该进一步形成一个链表操作习惯：链表题看到"删除节点"，首先考虑应该修改哪个节点的 next，让链表绕过需要删除的节点，而不是像数组一样想着移动后面的所有元素。
